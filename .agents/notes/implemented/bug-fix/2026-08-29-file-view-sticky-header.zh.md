# Agent Note: File 视图标题栏在滚动内容时保持固定

状态：已实现

[English](2026-08-29-file-view-sticky-header.md) | 中文

## 问题

文件标签页（`ui-conversation-files` 的 `FileView` 组件渲染的 `conversation.view`
视图）位于 `ConversationRoot` 单个常驻滚动区（`.scrollBody`，单轴）内部。它自己的根节点没有滚动容器，内容区域使用 `overflow: auto`，因此当文件文本超出视图高度时，该区域会变成一个独立的第二个滚动区。在内容上滚轮只能移动内容；路径横幅和查看/编辑/差异工具栏会随着内容一起移走。文件很长时，标题栏会在任何按钮或未完成指示器可见之前就滑出可视区，导致 `保存`（及其冲突重载链接）需要先滚回顶部才能找到它们。

## 决策

让 `.root` 成为唯一的滚动区，并用 `position: sticky; top: 0` 将 `.header`
钉在顶部。根节点本来就已填满内容盒（`flex: 1`、`min-height: 0`），且不拥有其他
滚动区（编辑模式下的 CodeMirror 缓冲区和差异模式下的左右对比面板都是就地渲染，
而非嵌套滚动区），因此将其提升为单轴滚动区（`overflow-y: auto` +
`scrollbar-gutter: stable`，与 `.scrollBody` 一致）即可让一个面滚动整个标签页。
标题栏通过 `top: 0` 吸附；`z-index: 1` 使其底部边框位于同级粘性横幅之上
（这与活动阶段下的输入台使用的排序规则相同）。内容内边距从 body 移至统一的
`padding: 16px`，使可见文本与钉死的条带自身的 `padding: 8px 16px` 保持清晰。

## 考虑过的替代方案

**保留 `.body` 作为其内部独立滚动区。** 已拒绝——这正是本问题所在；在单轴主机内部的嵌套滚动区会隐藏所有同级元素，包括工具栏和未完成草稿指示器。

**让 `FileView` 的根节点滚动内容但不使标题栏粘性固定。** 已拒绝：非粘性的标题栏会随着内容一起移走（只有底部外部打开操作保持可见），所以保存/差异控件仍然需要在滚回顶部后才能访问。

**使用比一行更高的固定标题栏。** 因范围限制而拒绝：要求是让现有标题栏保持在原处，而不是扩大它；多行钉死的 chrome 会改变工具栏的布局，属于单独的后续跟进。

## 影响

当内容超过视图高度时，在内容上滚轮会滚动它，同时路径和查看/编辑/差异控件
仍钉在顶部——保存按钮（及其冲突重载链接）无需滚回顶部即可访问。较短文件不变：
根节点刚好填满列，标题栏停在 `top: 0` 的原始位置。粘性条带带有背景色，避免
内容从其下方透出，同时其底部边框线读作标签页的分隔线。未来若有视图在此主机下
添加自己的滚动区（例如图像查看器），必须采用相同的单一滚动区选项，而不是引入
第二个隐藏的滚动区。
