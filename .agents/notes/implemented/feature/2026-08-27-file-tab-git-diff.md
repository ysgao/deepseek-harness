# Agent Note: Side-by-side git diff in the session File tab

Status: implemented

English | [中文](2026-08-27-file-tab-git-diff.zh.md)

## Problem

The session File tab ([File preview as a conversation tab](2026-08-26-file-preview-conversation-tab.md)) always shows a file's current content, with no awareness of git at all — even though the Files tree sibling ([per-file git status](2026-08-27-workspace-files-git-status.md), built on the [sibling-browser](2026-08-24-workspace-files-sibling-browser.md) foundation) already tracks and surfaces which files are changed. There was also no diff computation anywhere in `host-apiproxy`: the one existing diff surface, `DiffBlock` in `ui-primitives`, renders a stacked removed-then-added chat card from model-tool-call `FileDiff` hunks (`packages/fs/tool-fs/src/diff.ts`'s `computeHunkDiffs`), not from git, and is built for a compact inline card rather than a dedicated full-file view.

## Decision

**New host capability, `workspace.gitFileDiff({ workspaceId, path })`**, mirroring the existing `workspace.gitStatus`/`gitCommitAll`/`gitDiscardAll` pattern ([git-status Agent Note](2026-08-27-workspace-files-git-status.md)) in `packages/host/apiproxy/src/workspace-git.ts` and `src/api-proxy.ts`. It returns `{ oldText: string | null, newText: string | null }` — full file text on both sides, not context-limited hunks, since this is a dedicated full-file view (`ReadBlock` already shows the whole file un-capped in this same tab). `oldText` comes from a new `workspaceFileAtHead(path, filePath, signal)` in `workspace-git.ts` (`git show HEAD:<repo-relative-path>`, folding any non-abort failure to `null` — new/untracked/renamed-from-elsewhere, or an unborn branch, are all "no committed blob," not distinguished from each other). `newText` reuses the existing `readWorkspaceFile`/`workspace.readFile` machinery, folding `directory-unreadable` to `null` (the file is gone from the working tree — an expected diff state) while `file-too-large` still surfaces as its own error. Unlike `gitStatus`'s quiet `isRepo: false`, a non-repository workspace fails loud with `git-not-a-repository` here (matching the write actions' stance): a diff without a repository is meaningless, not a legitimate empty state.

**New client primitive, `SideBySideDiff` in `ui-primitives`**, git-style two columns (old left, new right) each with its own line-number gutter — the side-by-side counterpart to `DiffBlock`'s stacked card. It aligns `diffLines` (the `diff` package, already a repo dependency via `tool-fs` and `ui-trajectory`) output into rows client-side: the host sends raw text, the client computes row alignment, the same division of labor `readFile`/`ReadBlock` already use for the plain view. A removed block immediately followed by an added block (a replacement) pairs lines row for row; the longer side's excess lines stand alone with the other column blank. No syntax highlighting and no height cap — matching `DiffBlock`'s own no-highlighting choice, and because this view is already a dedicated full-file surface rather than an inline card needing collapse.

**`FileView` (`ui-conversation`) gains a View/Diff toggle**, shown only when the opened path is `kind: 'text'` and has a pending git change (`Object.hasOwn(gitStatus.files, path)` — including the `U` untracked code, since an untracked file still meaningfully diffs as "all added" against nothing). `FileViewInjected` gains `getGitStatus`/`getFileDiff`, wired in `apply.ts` through the same workspaceId-resolution closure `readFile` already uses (factored into a shared `resolveOwningWorkspaceId` helper to avoid tripling the lookup). Git status is fetched once per path open (deciding the toggle's visibility); the diff itself is fetched lazily, only when the user switches into Diff mode — not on every plain-view open. No live-refresh: the tree's own explicit-refresh control is the precedent for a future follow-up, not something this change duplicates.

The new type, `WorkspaceFileDiff`, threads through the same five-package re-export chain `WorkspaceGitStatus` already uses: `host-apiproxy` (`api/workspace.ts` → `api/index.ts`) → `client/connection` (`api.ts` → `index.ts` → `fixture.ts`) → `api/remotes` → `client/runtime` (`contract/workspaces.ts` + `workspaces/service.ts`'s new `getWorkspaceFileDiff`) → `@deepseek-ai/dsh-client-runtime/client`. `IWorkspaces`' other two implementers (`test-support/client-runtime`'s `TestWorkspaces` double and the wire test doubles in `client/connection`/`client/runtime`'s `tests/`) gained the matching method so the interface stays sound at compile time.

## Alternatives considered

- **Compute context-limited hunks on the host** (reusing `computeHunkDiffs`'s `structuredPatch` pattern) instead of sending full text. Rejected: a side-by-side view wants the whole file (matching `ReadBlock`'s existing un-capped posture in this same tab), and hunks-with-context is a shape `DiffBlock`'s compact chat card needs, not this dedicated full-file view — reusing it would mean re-deriving full text from hunks client-side for no benefit.
- **Diff `git diff`'s own textual output instead of fetching both full texts.** Rejected: parsing unified-diff text back into structured rows duplicates work the `diff` package already does correctly on two plain strings, and the host would still need a separate working-tree read for binary detection/size bounding, so nothing is saved.
- **Show the diff automatically whenever a file has changed, instead of an opt-in toggle.** Rejected: changes the default behavior of the existing plain-view path with no way back short of re-opening the file, and forces every changed-file open to pay the diff fetch even when the reader just wants current content.
- **Resolve a rename's old path from git status's paired rename record**, so an `R`/`C` file diffs correctly instead of appearing fully added. Deferred: `workspace-git.ts`'s porcelain parser already discards the paired original-path field (`workspaceGitStatus`'s own doc comment), and threading it through would touch the status wire shape for a v1 that ships without it; tracked as a known limitation in `packages/host/apiproxy/README.md`.

## Consequences

- `WorkspaceApi`/`IWorkspaces` both widen (`gitFileDiff`/`getWorkspaceFileDiff`); per `packages/CLAUDE.md`'s capability-seam rule this was designed for both current consumers (`ui-conversation`'s File tab today; the Files tree is a plausible future caller) rather than shaped around one call site.
- `ui-primitives` gains a new dependency, `diff` (already used the same way by `tool-fs` and `ui-trajectory`, so no new supply-chain surface for the monorepo as a whole).
- A renamed/copied file's diff shows as fully added rather than following the rename, and only `kind: 'text'` files offer the toggle at all (binary/markdown/image excluded in v1) — both documented in `packages/host/apiproxy/README.md`'s Known Limitations.
- `host-apiproxy`, `test-support/client-runtime`'s `workspaces.ts`, and `ui-primitives`'s `SideBySideDiff.tsx` reach 100% line/branch/function coverage in their own package suites (two narrow-window `signal.aborted` re-checks — the second of two sequential fallible git/fs calls — are `v8 ignore`d, matching `workspace-git.ts`'s own existing narrow-window guards for `commitAllChanges`/`discardAllChanges`); `ui-conversation/src/client/*` remains under the pre-existing GUI-debt coverage exemption (`vitest.config.ts`) that predates this change, though `FileView.client.spec.tsx` still gained behavioral tests for the toggle.
